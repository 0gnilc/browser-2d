## 本次补齐的工程缺陷

旧库中的 `device.count` 和 `device.status` 可保存 SQLite 64 位整数。原入口只检查其存储类型，超出 JavaScript 安全整数范围时仍迁移到 v4，随后公共设备查询抛出 ZodError。现有数值边界表已补入这两列，打开数据库时即拒绝不支持的值。新增 10 项实际数据库用例覆盖正负首个越界值、SQLite 极值和合法边界。拒绝后源文件字节、版本和记录保持不变；合法值迁移后及再次打开仍可经公共仓储读取。没有改写既有 SQL 迁移。

Chrome 清理原先在删除用户目录之前写入 `released`，并吞掉删除异常。现新增仅用于自有 Chrome 的持久化 `stopped` 状态，确认进程停止后先记录该事实，再删除目录，成功才写入 `released`。删除失败返回 `CLEANUP_FAILED`，资源义务和容量继续保留。重启后可重试部分删除的目录，无需依赖已删掉的调试发现文件，也不依据磁盘 PID 杀进程。4 项回归覆盖 prepared、已启动未连接、已连接的失败恢复，以及取消期间不返回的删除操作。故障只注入文件系统删除边界，数据库、调度服务和已启动的 Chrome 均为真实实例。

## 本次补齐的验收入口

`pnpm verify:formats -- --target=<目标>` 验证当前干净提交构建的 ZIP 或 AppImage。它先检查源提交、锁文件和完整产物清单，随后运行同一份文件两次，再复核哈希。macOS 从 ZIP 解压出的应用运行。Linux 直接 FUSE 启动原 AppImage，实际 worker 路径必须位于挂载目录。静态 ASAR 和 fuses 仍检查其解包内容，不把解包可运行代替 FUSE 运行。该命令现由正常 native CI 执行，不再依赖硬编码旧 Actions run 的诊断工作流。

新增开发入口场景实际启动 `dev:ui` 和 `dev:worker` 对应脚本。前者使用独立 Chrome 验证预览提示、业务及工作不可用、无特权全局，并确认服务退出。后者两次使用同一临时数据库启动，核对真实 worker 所有权记录、零窗口调试目标、正常关闭、进程消失及数据库保留。原有 HMR 和源码重启场景继续执行。

## 本轮验证与证据

原基线完整 `pnpm verify` 已通过。结果为 36 项边界、30 项组件、59 项存储及 Chrome、31 项凭据与进程所有权、27 项更新、22 项发布工具、1 项 Chrome 观察器和 31 项 Electron 场景。通过原套件后仍以实际临时库和故障探针复现上述两处缺陷，说明新增回归确实补足原覆盖范围。

本轮最终提交的完整本地验证和四目标预览结果在验收结束时补入此节。当前不得将旧矩阵冒充为本轮修改后的运行结果。已重算上一轮 70 份归档证据的 SHA256，全部一致。旧证据对应 `f52238f`，本轮证据将单独绑定源提交、锁文件和新产物哈希。
