# 0.1.0 分支汇总

2026-11-01 根据用户要求汇总所有现有分支，在 PR #9 的 CI 通过后合并 main，并清理无用分支和工作区。

## 内容与历史

汇总前的验收版本为 `9c0bd1ac88ca4469a014ecd0d0dd0c1dd02bad53`。50 个本地分支中，24 个已是该版本的祖先，17 个分支的独立提交已有等价补丁，另外 7 个是诊断分支，2 个是旧备份及旧业务分支。14 个远程分支头均与对应本地分支一致。

使用 `ours` 合并已核对的 26 个非祖先分支，保留全部提交历史，以当前验收代码解决旧实现与诊断版本的差异。合并后逐个确认原始 50 个分支头均为 HEAD 的祖先，并确认完整文件树与汇总前完全相同。以下记录支持后续删除分支引用而保留提交。

旧 tataxingqiu 分支的外部充值流程、AdsPower、无限重试及旧字段转换不进入当前受控 Chrome 实现。诊断分支的单平台工作流与临时探针保留在历史中；当前常态四目标验收入口继续使用。未发现尚未纳入的现代工程功能。

## PR 与验收

[PR #9](https://github.com/0gnilc/browser-2d/pull/9) 的连接器授权已恢复。首次 PR CI 的 Windows、Intel macOS、Apple Silicon macOS 通过；Linux 在 `apt-get update` 下载 Ubuntu 镜像索引时停滞，40 分钟任务上限将其取消，项目安装、测试与打包尚未启动。依据为 [原始 Linux 任务](https://github.com/0gnilc/browser-2d/actions/runs/41251403050/job/124685502934)。本次重新启动完整原生矩阵，不增加超时或放宽断言。

版本号继续为 `0.1.0`。这是工程与预览基线，正式签名、公证、更新源及分发条件仍由 Issue #6 跟踪；Windows 偶发 Chrome 获取超时仍由 Issue #8 跟踪。完整范围见 [P0–P6 验收报告](p0-p6-acceptance.md)。

清理只针对已汇总、未在使用且没有未提交内容或独有忽略文件的工作区。有未归档内容的工作区保留，避免在整理分支时丢失文件。
