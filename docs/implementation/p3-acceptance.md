## 已实现的行为

旧 P1 定时服务及顶层任务 API 已退出。新的 `work.start`、`work.cancel`、`work.getCommand`、`work.getSnapshot`、`work.subscribe` 贯穿界面、preload、main 和 worker。调度、业务数据及资源义务共用 worker 独占的 `data.db`，没有第二个任务数据库写入者。

| 能力       | 验收行为                                                                                      |
| ---------- | --------------------------------------------------------------------------------------------- |
| 持久化命令 | 相同 ID 和输入返回原始回执；不同输入冲突；拒绝结果也保持稳定；响应丢失可查询原命令            |
| 任务状态   | queued、starting、running、stopping，以及 completed、cancelled、failed、interrupted           |
| 并发限制   | 最多两台执行设备、四个页面单位；接纳时固定 pageCount 和设置版本；派发时一次性预留全部需求     |
| 设备互斥   | 非终态与未清理资源均阻止相同设备新任务；受影响设备不能被编辑或删除                            |
| 取消       | 先持久化意图，再中断执行；排队任务无需创建资源；活动任务清理完成后才成为 cancelled            |
| 超时       | 执行期限 30 秒；清理单次期限 1 秒，每个 worker 生命周期最多尝试三次；不释放尚未结束操作的容量 |
| 资源恢复   | 先记录意图再产生副作用；迟到的成功创建仍被清理；借用资源不删除；所有权不明或清理失败继续阻塞  |
| 崩溃恢复   | 四种旧非终态全部变为 interrupted，只核对和清理资源，不自动重新执行                            |
| 快照       | 包含所有活动任务与未清理资源，以及最近 100 条终态；失联主动通知，迟到快照不能恢复旧连接       |

本轮任务明确标注为受控执行，默认执行三秒。使用真实业务设备 ID，但不连接 AdsPower/Puppeteer，不消费材料、不生成真实执行历史，也不为受控任务解密业务凭据。页面单位由受控驱动建模，不代表真实浏览器页面已验收。

## 进程与数据边界

所有权记录采用 `worker-owners/<nonce>.json`，每个启动者只更新或移除自己的文件。先原子发布记录，再检查其他启动者；发送初始化之前才登记确切子进程 PID。真实双宿主子进程测试覆盖并发声明与 pending→authorized 的观察竞争。

没有初始化授权的子进程五秒后退出。授权后使用一秒心跳、五秒租约。旧 PID 存活或状态不明时阻止接管，不依据磁盘中的 PID 终止进程。PID 重用可能导致保守拒绝，不能因此宣称另一个进程已被确认死亡。

关闭依次停止接纳、记录取消、中断执行、清理自有资源、提交状态、关闭 SQLite 并确认进程退出。协作预算十秒，强制终止及确认预算五秒。强制或未确认退出不会被报告为正常关闭。清理失败时保留 stopping 和资源义务，重启再核对。

P2→P3 迁移先验证已有 schema 与 SQL 校验值前缀，备份全部已有表及 WAL 已提交数据，再仅执行 003。测试确认业务行、旧处理中材料、设置版本和凭据引用不变，失败会回滚。旧 `synthetic.sqlite3` 不再读取，原文件没有被删除。

开发协调器实测覆盖构建失败保留原进程、源码恢复后等待旧进程退出再替换，以及强制关闭失败不启动替代进程。测试使用开发模式的回环调试连接；普通成品验收没有启用调试器或放宽 fuses。

独立资源服务试验实际观察延迟创建、回执丢失、操作封锁后的最终不存在、借用资源保留和清理拒绝。它是测试子进程，不是浏览器适配器。真实 Electron 试验另行观察创建后未记回执、清理中崩溃、心跳丢失、宿主强制结束、未初始化过期，以及获取、执行、释放三阶段不响应取消时的非零退出。

测试判断进程是否退出时观察实际 PID，不把 Playwright 调试连接关闭当作宿主退出证明。Windows 不执行两个 POSIX SIGSTOP 场景，但执行三阶段便携式挂起、宿主死亡和其他恢复用例。

首轮原生 CI 发现 Windows 历史快照夹具逐条持久化写入超过测试期限，以及开发测试启动观察问题。历史夹具改为一个准备事务，保留真实回执重放并增加旧资源保留断言。开发测试避免重复恢复未变化的源码并保存完整输出。开发构建与控制标准输入分离，宿主死亡试验改为读取并观察实际 Electron 主进程 PID。修正后按最终提交重新运行原生矩阵。
