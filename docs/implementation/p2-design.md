# P2 实施边界

本轮补齐 P0、P1 的已确认遗漏，完成 P2，停在 P3 之前。工作基于 `585f78c`，跟踪事项为 [Issue #3](https://github.com/0gnilc/browser-2d/issues/3)。所有开发验收使用人工数据和临时目录，不打开真实用户数据库。

现有 `apps/desktop` 负责窗口、preload、IPC 来源验证和工作进程退出。`apps/worker` 独占业务数据库。`packages/contracts/public` 定义界面可调用的具名 API，`host` 定义私有进程协议。P1 合成任务继续使用独立的 `synthetic.sqlite3`。

P2 新增设备、材料、历史、设置四组 API。界面只提交业务输入并读取结果，不管理 SQL、迁移步骤或凭据引用。每个切片都验证调用、事务、刷新和重启读取。完整界面改版、任务调度和真实浏览器驱动仍分别属于 P5、P3、P4。

## 存储与迁移

生产业务路径保留 `~/kys/data.db`。开发和测试显式使用独立目录。旧库迁移前确认旧程序已关闭，再取得 SQLite 独占访问。SQLite 锁证明访问被排除，不能证明一个空闲旧进程已经结束。

worker 使用一个业务连接，设置 `locking_mode=EXCLUSIVE`，执行 `BEGIN EXCLUSIVE; COMMIT`，并在整个运行期间保留独占模式。备份在同一连接上使用 SQLite backup API，位于 SQL 事务之外。实际探针已确认该组合可备份未 checkpoint 的已提交 WAL 行，同时拒绝第二个连接读取。

先检查已知表结构、字段类型、版本和迁移校验值，再建立并验证备份。未知结构、更高版本或已执行 SQL 被修改时拒绝迁移。旧表原地接入，保留 ID、序列、时间文本、空值、空字符串和已有重复行。结构变更、迁移记录及凭据引用切换在同一事务中提交。失败保留原库和备份，不自动恢复覆盖新数据。

材料新增在事务内拒绝重复身份元组，迁移不删除已有重复行。导入保留可选字段的空位置，返回原始行号和实际提交数量。状态 0 可筛选。认领通过单条原子更新完成，留在 worker 内部。处理中记录的编辑、重置和删除返回冲突。迁移不重置业务状态。

历史的 `day` 与 `year` 独立保留。导出继续使用旧格式 `card|month|day|cvv`，包含全部匹配记录和末尾换行。日期按原有无时区时间文本作包含边界的比较。修复历史行删除入口，移除没有定义行为的行重置按钮；筛选重置保留。

## 凭据与启动

desktop 是 `credentials.enc` 的唯一写入者。使用 Electron 的异步 safeStorage API。先加密、原子替换文件并重新解密验证，再让 worker 事务提交设置及 `secretRef`。设置使用版本比较，过期更新返回冲突。失败或响应丢失时不删除旧密文，新建但未引用的密文可暂留。

旧明文只通过初始化阶段的一次性私有协议传给 desktop，不出现在公共响应、事件、错误或日志中。worker 等待已验证的持久化引用后，才在迁移事务里删除原配置项并提交引用。缺失或无法解密的引用阻止业务就绪。

Linux 没有安全存储时，持久化保存明确失败。用户可选择仅会话保存新录入的凭据；会话引用不落库，重启后显示未配置。会话内存不能满足旧明文迁移的持久化条件，因此不能以会话模式绕过旧凭据迁移失败。

旧库迁移确认使用业务就绪之前可显示的原生确认界面，避免等待 worker 就绪后才创建确认界面的死锁。开发验收可显式声明旧程序已经关闭，仍需通过真实数据库锁验证。保存的迁移备份可能包含原有明文，报告会区分历史备份与新凭据写入。

## 验证顺序

1. 补齐公共契约及 workspace 依赖图检查，加入违反规则时必须失败的 fixture。
2. 验证独占锁、WAL 备份、迁移回滚、版本及校验值拒绝，然后接入仓储。
3. 依次验证设备、材料、历史和设置，通过真实 IPC 刷新并重启读取。
4. 注入密文文件写入、解密、数据库提交失败，确认旧引用和旧库可恢复。
5. 独立审阅后，执行四个原生目标的测试、构建和仓库外成品验证。

P1 的签名、公证、更新、Windows 11 实机安装和完整 Linux 桌面覆盖限制保持明确，属于 P6 验收范围。

## 设计比较

三个候选均选择 worker 独占 SQLite、同连接备份和 desktop 密文保存。采用候选 B 的未完成初始化不暴露业务仓储结构，加入候选 A 的设置版本比较，保留候选 C 的原地接入旧表方式。未选择影子数据库替换，避免锁和 WAL 文件切换增加恢复路径；未选择通用反向 RPC，限制凭据通道用途。

实现中的接口与验收偏差将在本文更新，不另建相互冲突的规范。

P2 新界面接管全部活动 CRUD 调用方后，移除不再运行的根目录 `src` 和 `electron`。只删除其中的数据库模块会使旧浏览器代码留下悬空依赖，因此旧入口一并退出。P4 的行为对照仍可从冻结提交 `a0567c5` 读取；本轮没有实现或启用真实浏览器流程。旧 Forge 和根 Vite 配置的最终清理仍属于 P6。

参考 [SQLite 独占锁](https://sqlite.org/pragma.html#pragma_locking_mode)、[SQLite 备份](https://sqlite.org/backup.html)和 [Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)。实际行为以本项目锁定依赖和测试记录为准。
