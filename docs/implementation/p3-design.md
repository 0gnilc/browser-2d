# P3 调度与恢复

本轮实施 P3，停在 P4 之前。基础提交为 `a28df3b`，跟踪事项为 [Issue #4](https://github.com/0gnilc/browser-2d/issues/4)。只运行明确标注的受控验证任务，不连接浏览器、不消费业务材料、不写入真实执行历史，也不为验证任务解密凭据。

P1 独立定时任务服务退出，新的调度器使用 worker 已独占的业务 SQLite 连接。三个持久化表分别保存不可变命令结果、任务状态与配置快照、资源意图及清理义务。同步事务管理这些事实，异步执行器只持有当前进程内的 Promise 和取消控制器。

公共 API 统一为 `work.start`、`work.cancel`、`work.getCommand`、`work.getSnapshot`、`work.subscribe`。设备使用业务设备的数字 ID。start 成功表示接纳已经落库，cancel 成功表示取消意图已经落库。重试同一输入与 commandId 返回原结果，换输入则冲突；响应丢失时查询原命令，不创建另一个命令代替。

任务状态包含 queued、starting、running、stopping 和 completed、cancelled、failed、interrupted。四种非终态均占用设备身份。调度默认最多同时执行两台设备、占用四个页面单位；单任务需求取接纳时的 pageCount 配置。超过全局容量的需求直接拒绝，排队任务不占执行容量。派发时一次性预留全部页面需求并写入资源意图，避免部分预留造成相互等待。

任务接纳时固定设置版本和非敏感执行配置，之后修改设置只影响新任务。活动任务或未清理资源关联的设备不能被更新或删除。控制任务不改写旧材料的处理中状态。

资源使用稳定操作 ID 和所有者标识。先提交意图，再创建可由外部测试进程观察的受控文件资源。取消后迟到的成功创建结果仍必须记录并清理。只有可以证明操作不会再产生迟到资源的最终不存在结果，才能释放未知资源的容量。自有资源核对所有者后删除，借用资源保留，身份不明确则继续阻塞。

清理失败停留在 stopping，并显示未完成的清理义务；不能以 cancelled 或 completed 误报完成。恢复首先把旧 queued、starting、running、stopping 全部标为 interrupted，保留资源义务。恢复只核对和清理资源，不重新执行旧任务。完整快照包含所有活动任务和未清理资源，以及有上限的终态历史。

desktop 在子进程 spawn 后、发送初始化之前，将 PID 与随机授权标识刷入独立所有权记录。未收到授权的子进程不能打开数据库，并会超时退出。授权后的子进程使用带标识的心跳租约，不依赖 parentPort 未公开的关闭事件。旧记录的 PID 仍存活或状态不明时阻止接管，不依据磁盘中的 PID 杀进程。

关闭协调器先停止接纳、提交取消、取消执行、清理资源和提交状态，再关闭数据库并等待进程退出。预算为十秒协作关闭和五秒强制终止及退出确认。只有当前仍受监督的子进程可以被终止，发出终止请求不算退出证明。强制或未确认退出不报告正常关闭，也不允许开发热重启启动第二个写入者。

工作进程失联会主动向界面发送不可用状态。主进程连接代次与 worker 的 epoch/revision 共同阻止迟到快照把连接错误恢复成正常。订阅先建立监听再读取初始状态，卸载时释放监听。

P2→P3 升级先验证现有 schema 与已执行 SQL 的校验值前缀，通过同连接 SQLite 备份验证全部既有表，再仅执行待执行迁移。保留设置版本、凭据引用、业务行与旧材料状态，不重放 002 或旧明文初始化逻辑。

设计以候选 B 的同步仓储和异步执行结构为基础，加入候选 A 的最终不存在判定、迟到创建和清理失败规则，并保留候选 C 的过期观察保护。未增加事件溯源框架或独立槽位表。原始候选中 A 的安全评分最高，B 加入上述必要修正后具有较清晰的实现与测试边界。

验收包含数据库确定性测试、独立资源服务的延迟创建试验、真实 Electron 的崩溃和宿主失联、开发源文件重启，以及四个平台目标的成品验证。受控文件和测试服务验证 P3 协议，不代表 AdsPower 或 Puppeteer 资源清理已经验证。P4 需要另行接入并验收真实适配器。

参考 [Electron utilityProcess](https://www.electronjs.org/docs/latest/api/utility-process)及 [parentPort](https://www.electronjs.org/docs/latest/api/parent-port)。最终实现与验收证据在 P3 验收记录中汇总。
