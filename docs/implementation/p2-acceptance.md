P2 业务数据库仍由 worker 独占。增加了以下操作及对应的最小界面。

| 切片 | 行为                                                                               |
| ---- | ---------------------------------------------------------------------------------- |
| 设备 | 新增、编辑、删除、刷新；新设备默认停止，零金额、空值和空字符串保留                 |
| 材料 | 新增、编辑、按行导入、分页、状态筛选、重置、删除和清空；原子认领保留在 worker 内部 |

| 设置 | 类型化读写、版本冲突检查、凭据保留/替换/清除，以及显式持久或会话保存               |

导入返回每个原始行号的结果，成功数量等于实际提交数量。有效行在一个事务内写入。保留空字段和地址中的短横线，兼容明确的旧分隔方式与月/年格式。重复材料判断和最终更新使用相同的省略值语义，不能用 `undefined` 绕过重复检查。空筛选条件不排除空值记录，状态 0 仍参与筛选。

历史的 `day`、`year` 和无时区时间文本分别保留。导出沿用 `card|month|day|cvv` 及末尾换行，不把 day 静默换成年份。材料编辑只提交修改过的字段，旧记录的未修改字段不会被新写入规则误拒绝。金额支持小数，表单与存储规则一致。

新的活动调用方统一使用 `window.browser2d`。根目录旧 `src` 和 `electron` 已退出，避免保留另一套可继续扩展的 CRUD API。原实现仍可通过 `git show a0567c5:<路径>` 对照。P4 的真实浏览器流程尚未重新接入。

## 数据与凭据

生产默认保留 `~/kys/data.db`。开发和验收使用独立目录。迁移先取得用户对关闭旧程序的确认，再取得 SQLite 独占访问，并在 worker 生命周期内保持独占。锁只能证明旧连接不能访问数据库，不能证明任意空闲旧进程已经退出。

迁移前通过同一个 SQLite 连接生成包含已提交 WAL 数据的一致性备份，验证完整性、结构、行内容与自增序列。保留原表、ID、序列、空值、重复行和时间文本。SQL 文件校验值、迁移记录、凭据引用及旧明文删除一同提交；失败回滚。未知结构、更高版本或已执行 SQL 被改写时拒绝写入。恢复测试把备份复制到新目标再打开，未覆盖原库或备份。

备份位于业务数据库旁的 `backups/`。元数据标明是否包含旧明文。历史备份可能包含原来的 API Key，这是保留原始数据的恢复副本，不是新凭据明文落盘。不会自动使用旧备份覆盖已经产生新数据的数据库。

desktop 使用真实 OS safeStorage 异步 API 保存 `credentials.enc`，先加密、刷盘、原子替换并重新解密验证，再让 worker 提交引用。失败保留原引用；未引用的密文暂留，未做自动回收。公共读取、事件及错误不返回明文或 `secretRef`。Linux 无安全存储时拒绝持久化，可明确选择仅会话保存新凭据。会话替换成功后移除旧的持久引用，重启显示未配置；它不能绕过旧明文迁移所需的安全持久化。

初始化阶段的私有凭据应答与一次性 nonce 关联。测试确认错误 nonce 会被拒绝，等待迁移确认时也能协作关闭，且不会提交迁移。

所有本轮实现与验收使用人工 fixture。未读取或迁移真实 `~/kys/data.db`，未连接 AdsPower 或真实业务账户。
