# P2 grounding and design brief

User authorized P0/P1 omissions and P2 only, stopping before P3. Base is 585f78c. Final architecture and phase scope in docs/monorepo-refactor-plan.md are binding. Do not redesign stack or implement scheduler/browser integration/full P5 UI/P6 release.

Existing worker owns synthetic.sqlite3, main owns process lifetime and named IPC; preserve this. Add business data.db independently. Legacy schema is tests/fixtures/legacy-schema.sql, repositories electron/db/*.js, consumers src/views/*. New packages/contracts/public is the only renderer API, host is private. Main never opens business DB. Existing foundation acceptance docs/implementation/p0-p1-acceptance.md. Proven enforcement omission is scripts/check-boundaries.mjs scans apps only, not public contracts or complete dependency graph.

Legacy business data preserves integer IDs, sqlite_sequence, timestamps formatted UTC+8 without timezone, nulls/empty strings and duplicates. Device symbol not unique. New writes allow zero and explicit null clears. Material statuses 0–6; status 1 is processing. Atomic UPDATE RETURNING claim is worker-internal. No reset-on-start migration. New import must preserve empty optional positions, accept four required fields, report each original line and actual committed count. New duplicate tuples rejected transactionally without removing old duplicates. Pagination defaults 20; status zero valid, shared filter/count snapshot. Claimed material mutation conflicts.

History day and year are distinct nullable columns; preserve both, legacy export card|month|day|cvv with trailing newline, all filtered rows, inclusive original timestamp range. History row reset is a broken old button; filter reset works. Dormant saveHistory dedup has no active callers and is not a behavior to port.

Settings keys adsPowerUrl, adsPowerApiKey, viewportWidth, viewportHeight, pageCount. Typed get/save; no generic config read exposing key. Explicit retain/replace/clear secret action. Desktop owns encrypted atomic credentials.enc, worker stores secretRef only. Encrypt+persist+decrypt verify before DB ref swap; on failure old reference remains valid. Legacy plaintext transfer only through narrow private bootstrap protocol, never public DTO/event/error/log. Migrate plaintext only after confirmed encrypted save, retain backup and block business readiness on failure. Linux basic_text/unavailable must permit explicit session-only mode, no silent plaintext persistence.

Production first migration retains ~/kys/data.db; dev/tests use independent paths. Must ensure exclusive access against old process and during entire ownership, not only new app single-instance. Ordered checksummed SQL migrations, consistent SQLite backup includes WAL, validated integrity, transaction rollback, higher schema refusal before writes. Backups remain intact; known legacy plaintext in preserved backup distinguished from new secret writes. Unknown schemas/types should fail closed with actionable nonsensitive error.

Design task: usage-first type sketch, module map, signatures and migration/credential crash-state protocol. Propose structurally distinct approaches within fixed ownership. In particular prove SQLite exclusive lock + backup combination actually works, avoid promises within SQL transaction. Plan exact temporary fixture tests. Full P2 callers must use unique named API; obsolete legacy CRUD API deleted without implementing P3/P4.

Candidate rubric (for coordinator): migration correctness and crash recovery; credential boundary/atomicity; minimal maintainable API; P2 scope discipline; executable verification across runtime/platforms.
