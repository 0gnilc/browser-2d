# Owned Chrome family lifetime

The accepted plan requires cleanup of owned browser resources before releasing reservations, honest failure under bounded cancellation, cold recovery without replay, and no termination from an unverified stored PID. Borrowed sessions retain their original browser and tabs.

Current source is b1b592fbacd33f20fc2bf42a7583280b2b6f184d. apps/worker/src/browser/process.ts launches Chrome with a retained ChildProcess handle. It currently detaches on Windows only. chrome-driver.ts verifies owner token, exact profile path, browser hash, PID and process identity. An attached journal with absent browser PID is sufficient for released(). That function now saves stopped, awaits profile rm and saves released. Journal schema and transitions are in browser/journal.ts. Work service retains capacity on blocked cleanup and uses finite attempts, execution deadlines and cleanup signals. Desktop shutdown owns its separate budget.

The original cold-recovery test manually admits and acquires real Chrome, closes the browser from a separate CDP connection, confirms main PID absence, calls recover and cleans through a fresh driver. No work service, extra Node mkdir, missed await, mock contamination or launch-profile cleanup explains the leftover. Independent source trace is in p0-p6-audit-evidence/independent-profile-flow.md.

Native source-bound proof is p0-p6-audit-evidence/chrome-helper-recreation-proof.json. In run41203336758 source2dff459, Node9411 successfully removed the owned root. Orphaned Google Chrome for Testing Helper9429, PPID1, recreated it afterward. Its PGID9383 equals the owned main Chrome9412's inherited group and the test worker's group. That inherited group must not be signaled. Test teardown removed the recreated root, masking the defect in a passing assertion. DTrace had dropped events, so only the explicit positive entry/return sequence supports this finding; no absence claim follows.

The first false boundary is equating main browser PID exit with all owned writers stopping. Repeated rm or a post-removal stat cannot prevent future recreation. A dedicated OS lifetime witness must precede profile deletion and resource release. Keep the existing budgets and ownership checks. No disk-PID termination, arbitrary sleep, blanket retry, dependency upgrade or borrowed-browser termination is authorized by this evidence.

The implementation must decide persistent witness shape, spawned-before-attachment recovery, normal close, main-gone cold recovery, Windows behavior and pre-existing journals. Business SQL migrations001–004 are immutable. Any old record without sufficient ownership proof must remain visibly uncertain rather than receive fabricated proof. Do not disable normal Windows tasks simply because POSIX group primitives differ.

Useful regression fixture is a POSIX executable shell launcher that starts a gated helper, then execs real Chrome with the original arguments. Chrome retains the launched PID and passes existing CDP identity checks; helper inherits its group. After main exit, the helper can write the exact profile before exiting. A fresh driver must retain the reservation and profile while the helper is held, then delete only after the helper finishes. Cancellation while it is held must remain bounded and retain the cleanup obligation.

The design artifact must start from caller usage, then types/signatures/module ownership, state transitions, old-data policy, concrete tests and tradeoffs. Implementation follows after synthesis; no product code in candidates.
