## Reproducible findings

1. P6 native CI does not exercise the AppImage and ZIP formats that it produces. `.github/workflows/p1.yml:62` builds all distributables, then lines 64 through 71 exercise the unpacked application and DMG, NSIS, or DEB installation. RPM gets an additional Fedora exercise at line 72. `scripts/verify-package.mjs:33` scans for unpacked executable files. It does not launch an AppImage or extract and execute a ZIP. `scripts/verify-installation.mjs:26` selects only `.dmg`, `.exe`, or `.deb`. Current `scripts/` has no `verify-extra-formats.mjs`. These facts reproduce with `rg --files scripts`, `nl -ba .github/workflows/p1.yml`, and `git show origin/codex/p6-extra-formats:scripts/verify-extra-formats.mjs`.

   The diagnostic branch contains a working supplemental verifier and records three successful exact-byte exercises. However, that verifier hardcodes `sourceCommit = f52238f...` at line 11, downloads from the hardcoded `41184202293` workflow run, and reads `downloaded/release/<target>`. Its branch workflow replaces the ordinary workflow with a one-shot diagnostic matrix. This cannot validate future native outputs without modification. The fix is to parameterize the source directory and provenance, invoke the format check on the current job's exact outputs in the normal native matrix, and retain the direct FUSE mount assertion for Linux. Do not merge the hardcoded diagnostic workflow. Severity is P2, a repeatable acceptance gap. Prior exact-format evidence remains valid for its recorded bytes.

2. The root development entrypoints have incomplete runtime acceptance. `package.json:9` exposes `dev:ui`, and `scripts/dev-ui.mjs:4` selects the fixture bridge. `apps/ui/src/main.ts:10` loads that bridge, and `apps/ui/src/Foundation.vue:103` labels preview mode. `apps/ui/tests/Foundation.test.ts:534` and `apps/ui/tests/Business.test.ts:324` validate fixture behavior through component tests. No E2E invokes the actual `dev:ui` root command or `scripts/dev-ui.mjs`. Consequently the command's startup, transformed import environment, route rendering, and absence of an Electron or worker process have no runtime acceptance.

   `package.json:10` exposes `dev:worker`. `scripts/dev.mjs:15` branches on `--worker-only`, omits a renderer server at line 61, and passes the switch to Electron at line 89. `apps/desktop/src/main/index.ts:441` waits for the real `worker.ready` before returning without a BrowserWindow. `tests/e2e/scheduler.spec.ts:344` invokes `--worker-only` only to prove that a live stale owner rejects startup. No test starts `pnpm dev:worker` successfully or checks zero windows, isolated test storage, coordinated shutdown, worker PID termination, and restart behavior for that entrypoint. This follows from `rg -n 'dev:ui|dev:worker|worker-only|dev-ui.mjs' tests apps/ui/tests scripts package.json`. Severity is P2, an acceptance gap rather than a proved runtime defect. Add real command smoke tests with temporary data directories, without running these commands beside a source-mutating development test.
