## F1. P2 migration commits device rows that the public contract cannot read

Priority P2. This is an engineering omission that can be fixed now. It is unrelated to signing, update hosting or unsafe legacy purchases.

`apps/worker/src/storage/open-business-store.ts` lines 95 through 175 validates device.count and device.status as SQLite INTEGER but applies safe-integer bounds only to row IDs and material/history statuses. `packages/contracts/src/public/business.ts` lines 13 and 24 through 38 requires safe integers for device.count and device.status. Migration therefore accepts values that its subsequent public devices.list cannot return.

Reproduction script is `/tmp/browser-2d-p2-integer-probe.mjs`. Run from the repository root with `node /tmp/browser-2d-p2-integer-probe.mjs`. It creates fresh temporary copies of the committed legacy schema, inserts one artificial row for each column, loads the actual source through Vite SSR without starting a server, opens/migrates the DB, calls devices.list and inspects the resulting version. It cleans all temporary DBs and Vite cache afterwards.

For both `INSERT INTO device(symbol,count) VALUES ('large-integer',9223372036854775807)` and the corresponding `status` insertion, actual output was:

```text
openBusinessStore succeeded
devices.list: ZodError ... maximum 9007199254740991 ... path [0,"count"]
persisted user_version: 4
```

The status case reports path `[0,"status"]`. The backup exists but the live database has already committed migration. Users encounter an unavailable/error device list after a successful upgrade. The existing invalid-storage-class test at business-storage.test.ts lines 406 through 417 only covers a text material.status and does not catch these integer-range mismatches.

Smallest correction is to validate both device integer columns against the same safe bounds before backups or migration writes and return DATABASE_UNRECOGNIZED. Add regression fixtures for both signs and columns. Assert rejected open, no version/ledger commit and unchanged source bytes. Do not clamp, round or silently rewrite historical values.

## Deferred and intentionally excluded items

P0 does not prove historical installed-user count or the old Windows Squirrel identity. P1 preview identity is explicit and provisional. These facts matter for final installer compatibility and should remain release gates. They do not justify restoring the old toolchain or opening the user's real database.

Windows Server runner does not prove Windows 11 terminal UX. macOS 15 runners do not prove the macOS 14 minimum. Fedora container userspace does not prove a complete Fedora/Wayland desktop. Existing documentation acknowledges these coverage limits. They are not represented as completed product-support claims in this slice.

Signing, macOS notarization, production HTTPS feed, signed N to N+1 acceptance and formal publication remain user-deferred. The approved P4 scope excludes real payments, subscriptions, real-account workflows and the old infinite-retry logic. Their absence is intentional and is not an engineering defect.
